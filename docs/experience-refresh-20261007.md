# 工维联界面与兼容性收尾

## 范围
沿用真实项目、业务 API、数据库和三套身份。有限尝试平台兼容修复；四个已有页面按 image2 图实现。

## 设计依据
- output/imagegen/ 下四张图片使用 config.toml 当前供应商的 gpt-image-2 生成；每条提示均以用户指定前缀开始。
- 参考 https://linear.app/now/how-we-redesigned-the-linear-ui 的导航对齐、层次和减少视觉噪声；不复制新业务功能。
- 主协作：深绿 204px 侧栏、浅色工作区、约 2:1 对话与方案。方案：主体确认单与需求摘要。工单：横向筛选、表格与详情。资源：资源目录、轨迹、调用记录。
- 图中自动出现的“新增资源”、申请人等无后端支持字段不实现。设计数据不复制到运行界面。
- 动效限定 160–200ms 状态反馈，尊重 prefers-reduced-motion。

## 实施和验证顺序
1. Discovery 策略先补失败测试，再增加显式 platform_catalog；真实 AIC / Inbox / mTLS 校验不变，不静默重试默认发现。
2. 外部结果增加 continue 提示及待确认问题；不复活已取消任务，不用空 complete 代替人工确认。
3. 按图片重排 HTML/CSS，保留所有 API 与 DOM 业务事件钩子，技术数据默认折叠。
4. 全量单元测试、真实本机 AIP 流程、四页面/三尺寸浏览器检查。
5. 备份、部署、逐服务核验；最多一轮叮当实际重测。默认发现与叮当验收单独记录，不宣称 platform_verified。
